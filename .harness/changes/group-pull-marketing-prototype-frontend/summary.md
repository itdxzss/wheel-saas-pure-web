- 状态: 前端已部署第一套测试环境，待接口契约确认和人工验收

## 目标

按原型的信息架构升级拉群营销一级列表，并将原有创建抽屉替换为独立全页表单；页面继续使用 pure-admin-thin 和 Element Plus，不复制原型视觉体系。

## 完成范围

- 一级列表补齐任务 ID、任务名称、任务状态、阻塞原因和资源状态五项查询。
- 一级列表按原型顺序展示任务信息、任务状态、群组处理进度、拉人结果、营销进度、消息发送、异常情况、剩余资源、时间/操作九个合并字段。
- 新增 `/task/group-pull-marketing/create` 隐藏路由，沿用列表菜单权限与高亮。
- 新建页完成基础信息、目标群配置、角色账号与拉手配置、目标数据与营销消息、任务启动时机五个分区。
- 新建页覆盖原型字段、条件显隐、数字输入、开关、单选、多选、文件选择、空表和响应式布局。
- 删除旧创建抽屉和列表 composable 中无入口的创建状态，列表新增按钮改为路由跳转。
- 后端未返回的列表统计显示 `--`；合法零值保持 `0`。
- 未接入的群组筛选、账号资源、数据解析、模板快照和创建动作均展示可见提示，不调用旧创建接口，不注入演示数据。
- 候选群组选择按当前页范围合并 ID，并启用 `reserve-selection`，后续接入分页数据时不会覆盖其他页选择。
- TXT 文件在变更处理器中二次校验；成功率模式限制到 100%，模式切换时同步归一化已有值。

## 关键设计决策

- 静态 `/create` 路由排在动态 `/:id` 详情路由之前，避免被任务 ID 路由误匹配。
- 创建草稿保留在页面本地，不进入 Pinia；未来接口确定后在 API 与提交映射层接入。
- 五个业务分区分别拆成局部组件，最大单文件为 367 行，未超过项目 600 行红线。
- 列表刷新失败保留上一次成功数据，避免短时网络错误清空整个页面。
- 现有任务详情、群组明细和生命周期操作保持原路径与行为。
