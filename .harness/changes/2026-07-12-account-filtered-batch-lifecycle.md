# 变更记录：账号列表批量登录与批量离线

- 日期 / 分支: 2026-07-12 / `1.0.1-snapshot`
- 需求来源: Armada 账号列表批量操作需求
- 状态: 已完成

## 目标

让批量登录、批量离线优先操作勾选账号；未勾选时按当前列表最后一次成功查询的已生效筛选条件操作全部匹配账号。

## 范围

- In scope: 批量菜单名称、编辑中/已生效筛选状态、后端预估确认、ID/查询双执行路径、结果汇总展示与重复提交保护。
- Out of scope: 单行上线规则、迁移分组/抢登/删除的批量范围、协议层在线幂等逻辑。

## 影响模块

- 路由: 无变更。
- 页面: `src/views/account/index/` 账号列表。
- API: 新增批量预估、按查询批量登录、按查询批量离线调用；原 ID 调用保留。
- Store: 无全局 Store 变更；页面内维护已生效筛选快照和最新查询请求号。
- 权限: 无变更。

## 关键设计决策

- `searchForm` 只代表编辑中条件；只有最新一次“查询”请求成功后，条件快照才替换 `appliedFilters`。
- 页面首次查询成功前不存在 `appliedFilters`；此时批量登录、离线会被拒绝，路由分组也必须在首次列表查询成功后才生效。
- 查询失败保留原列表、总数和已生效条件；旧响应不能覆盖更新请求。
- 批量预估与用户确认后都校验已生效筛选版本；确认期间若新查询成功，终止旧范围执行并提示重新发起。
- 重置清空编辑条件后立即重新查询，成功后已生效条件才变为空对象，此时未勾选代表全部账号。
- 有勾选时预估和执行只提交 ID；无勾选时只提交已生效条件，不读取尚未查询的表单值，也不收集当前分页 ID。
- 执行前先调用后端预估；可执行数为 0 时提示，其余展示范围、匹配数、执行数和跳过数后二次确认。
- 批量登录入口不再由前端提前过滤封禁、解绑或抢登中账号，统一以后端分类为准。
