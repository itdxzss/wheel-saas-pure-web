# 拉群营销一级任务列表 V16 设计

## 背景

现有 `group-pull-marketing` 一级页面仍使用旧版原子字段，无法按《拉群营销\_PRD需求文档\_V1.2》第 16 章快速判断任务整体进度、拉人效果、营销效果、异常和剩余资源。本次只改一级任务列表的查询区和表格展示，不修改新增抽屉、任务详情、路由或任务操作流程。

## 目标

- 查询区完整使用现有列表接口已经支持的五个查询条件。
- 一级列表严格保留 PRD 第 16 章规定的九个合并字段，不增加额外独立业务列。
- 当前接口缺少新版统计字段时显示 `--`，不得在生产页面注入静态或随机演示数据。
- 保持现有分页、刷新、新增任务和任务生命周期操作可用。

## 查询区

| 页面字段 | 请求字段         | 交互规则                                     |
| -------- | ---------------- | -------------------------------------------- |
| 任务 ID  | `id`             | 正整数精确查询，可清空，回车触发查询         |
| 任务名称 | `keyword`        | 关键词查询，提交前去除首尾空格，回车触发查询 |
| 任务状态 | `status`         | 单选，可清空，选项沿用任务状态枚举           |
| 阻塞原因 | `blockReason`    | 单选，可清空，选项沿用阻塞原因枚举           |
| 资源状态 | `resourceStatus` | 单选，可清空，选项沿用资源状态枚举           |

点击“查询”时页码重置为 1 后请求列表；点击“重置”时清空五项、页码重置为 1 并重新请求。

## 一级任务列表

表格按以下顺序展示九个合并字段：

| 合并字段     | 默认展示内容                             | 缺失值规则                                             |
| ------------ | ---------------------------------------- | ------------------------------------------------------ |
| 任务信息     | 任务名称；任务 ID、任务类型、群组来源    | 文本字段缺失显示 `--`                                  |
| 任务状态     | 当前状态；主要阶段或阻塞原因             | 状态使用标签；阶段和阻塞原因均缺失时显示 `--`          |
| 群组处理进度 | 已进入转移终态群组数/目标群组数；进度条  | 任一统计缺失时不猜测比例，显示 `--`                    |
| 拉人结果     | 新增成功人数/计划人数；有效成功率        | 统计缺失显示 `--`；零值正常显示为 0                    |
| 营销进度     | 进行中群组数；完成群组数                 | 统计缺失显示 `--`                                      |
| 消息发送     | 成功、失败、未知消息数                   | “未知”为 0 时可省略；字段缺失显示 `--`                 |
| 异常情况     | 异常群组数、待补位群组数、封禁账号数     | 无异常且字段明确为 0 时显示“无异常”；字段缺失显示 `--` |
| 剩余资源     | 剩余有效目标数据、可用拉手；资源不足类型 | 资源不足使用警示标签；字段缺失显示 `--`                |
| 时间/操作    | 最近业务执行时间；现有任务操作           | 时间缺失显示 `--`；操作按现有状态规则生成              |

任务信息列固定在左侧，时间/操作列固定在右侧；页面宽度不足时允许表格横向滚动。复杂统计放在合并单元格内分层展示，不拆成新的独立列。

## 数据契约与兼容策略

`GroupPullMarketingTaskRow` 保留当前字段，并增加第 16 章所需的可选语义字段。前端直接消费后端明确返回的值，不根据旧字段拼造无法证明的业务统计。

前端语义字段定义如下：

- 任务信息：`taskType`、`groupSource`
- 状态阶段：`primaryStage`
- 群组进度：`processedGroupCount`、`targetGroupCount`
- 拉人结果：`joinedSuccessCount`、`plannedTargetCount`、`effectiveSuccessRate`
- 营销进度：`marketingRunningGroupCount`、`marketingCompletedGroupCount`
- 消息发送：`messageSuccessCount`、`messageFailedCount`、`messageUnknownCount`
- 异常情况：`abnormalGroupCount`、`replacementPendingGroupCount`、`bannedAccountCount`
- 剩余资源：`remainingTargetCount`、`availablePullerCount`、`resourceShortages`
- 时间：`lastExecutedAt`

`resourceShortages` 为资源不足类型数组，前端支持目标数据、拉手、水军、潜水管理员和营销管理员五种类型。上述新增字段全部为可选字段。接口未返回时只影响对应单元格的展示，不影响列表加载、分页或现有操作。后端字段名最终确定后，只在 API 类型或映射层收敛，不把响应转换逻辑散落到模板中。

## 组件边界

- `index.vue`：查询表单、路由跳转和页面装配。
- `constants.ts`：查询选项、九列定义、状态标签和纯展示格式化函数。
- `GroupPullMarketingTaskTable.vue`：九个合并单元格、分页、空状态与任务操作。
- `useGroupPullMarketingPage.ts`：查询状态、列表请求、重置、加载和错误反馈。
- `src/api/group-pull-marketing.ts`：查询参数和列表响应契约。

页面继续复用 `PureTableBar`、`ElForm`、`ElSelect`、`ElTable`、`ElProgress`、`ElTag`、`ElTooltip` 和现有分页组件，不新增 UI 基础组件。

## 页面状态与错误处理

- 加载中：沿用表格 `v-loading`。
- 空列表：展示“暂无拉群营销任务”。
- 接口失败：沿用页面可见错误消息，保留上一次已成功加载的数据，不伪造兜底行。
- 字段缺失：对应统计展示 `--`，零值不得误判为缺失。
- 分页变化：携带当前五项查询条件重新请求。

## 验证

- 查询契约测试：五个查询项都能进入请求，查询和重置均重置页码。
- 表格契约测试：九个合并字段按规定顺序存在，不出现旧版额外独立业务列。
- 展示函数测试：缺失值、零值、百分比和资源不足标签正确区分。
- 回归测试：新增抽屉、详情跳转、分页和任务操作事件仍可触发。
- 工程验证：运行相关 Node 测试、`pnpm typecheck`、相关 lint/stylelint 和 `pnpm build`。
