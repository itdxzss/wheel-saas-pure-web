# 渠道目标国家选项设计

## 目标

渠道管理的新增、编辑抽屉不再依赖尚未实现的买号 options 接口提供国家数据，而是复用现有 `listIpCountryOptions()` 国家主数据调用。

## 方案

- 渠道页加载时并行请求渠道 options 和 `/api/admin/countries/options?scope=ip`。
- 将真实国家映射为渠道现有的 `{ code, name, dialCode }` 结构。
- 过滤接口中的虚拟“混合”项；抽屉继续用既有固定选项展示“混合（不限国家）”。
- 映射后的国家同时服务渠道筛选和新增/编辑抽屉，默认区号继续使用 `phonePrefix`。
- 国家请求失败时国家列表为空并显示“目标国家加载失败”，其他页面布局和渠道请求不受影响。
- 不修改公共组件、路由或框架代码。

## 验证

- 单元测试覆盖虚拟项过滤与国家代码、名称、区号映射。
- 渠道页面契约测试确认调用现有国家接口。
- 运行相关测试、TypeScript 检查和 ESLint。

## 下拉展示补充

- 使用国家主数据返回的 `flag` Emoji，不新增图片或图标依赖。
- “混合（不限国家）”使用 `🌐`，真实国家按“国旗、国家名、灰色国际区号”展示。
- 选中后的输入框标签同样保留图标、国家名和区号。
- `targetCountry` 表单规则显式设置 `required: true`，用于展示必填星号并阻止空值提交；“混合（不限国家）”仍是合法值。

## 国旗代码兼容修复

- 国家主数据接口的 `flag` 可能返回 `AF`、`IN` 等 ISO2 字母，而不是可直接展示的 Emoji。
- 在共享的 `listIpCountryOptions()` 返回边界统一标准化：两位字母转换为区域指示符 Emoji；已有 Emoji 原样保留；空值使用 `iso2` 生成。
- 虚拟混合项的 `🌐` 原样保留。
- 渠道管理和现有 IP 国家选项共用同一标准化结果，不新增国旗组件或第三方依赖。
