# 拉群营销列表与新建页前端原型设计

## 背景与目标

现有 `group-pull-marketing` 已有任务列表、创建抽屉和任务详情，但一级列表仍是旧版原子列，创建抽屉也只覆盖当前后端已支持的小部分配置。此次以 `拉群列表原型.jpg` 和 `拉群详情.jpg` 为信息架构来源：列表对齐合并字段，新建任务改为独立全页表单。视觉继续沿用 pure-admin-thin 和 Element Plus，不复制原型配色或控件样式。

本阶段是前端先行。后端未确认的统计字段统一显示 `--`；新建页允许填写和切换本地草稿，但不得把未确认字段静默丢弃后调用旧接口。

## 方案选择

采用“完整前端壳 + 未定稿提交安全阻断”：先完成字段、分区、响应式布局和本地交互，保留真实列表读取与已有任务生命周期操作；最终创建动作展示接口待确认提示，不提交不完整配置。

未采用以下方案：

- 扩大现有抽屉：超长配置在抽屉内可读性和定位能力较差。
- 只把旧接口支持字段提交、忽略新字段：会让用户误以为页面配置已生效。
- 等后端契约完整后再做页面：不符合本次前端先行目标。

## 页面与路由

- 一级列表继续使用 `/task/group-pull-marketing`。
- 新增隐藏子路由 `/task/group-pull-marketing/create`，菜单高亮仍指向一级列表。
- 列表“新增拉群营销”跳转新建页；新建页“返回拉群任务”和“取消”返回列表。
- 现有 `/task/group-pull-marketing/:id` 任务详情路由和页面不在本次改造范围。
- 移除列表页面对旧创建抽屉的装配；旧抽屉无其他入口后删除，避免两套创建交互并存。

## 一级任务列表

### 查询区

保留并补齐五个现有查询条件：任务 ID、任务名称、任务状态、阻塞原因、资源状态。查询和重置都将页码重置为 1。

### 表格布局

按原型顺序展示九个合并字段：

1. 任务信息：任务名称、任务 ID、任务类型、群组来源。
2. 任务状态：主状态、主要阶段或阻塞原因。
3. 群组处理进度：已处理群组数/目标群组数及进度条。
4. 拉人结果：新增成功人数/计划人数、有效成功率。
5. 营销进度：进行中群组数、已完成群组数。
6. 消息发送：成功、失败、未知数量。
7. 异常情况：异常群组、待补位群组、封禁账号。
8. 剩余资源：剩余有效目标数据、可用拉手、资源不足标签。
9. 时间/操作：最近执行时间和现有任务操作。

任务信息固定左侧，时间/操作固定右侧，宽度不足时横向滚动。后端缺失字段显示 `--`，合法的零值显示 `0`；不得从旧字段猜测新统计值，也不得注入演示行。

## 新建拉群营销任务

### 页面骨架

页面顶部包含标题、返回按钮和简短流程说明。主体使用五个 `ElCard` 区块，桌面端表单以两列为主，复杂筛选和表格占满整行；窄屏退化为单列。底部使用页面内操作栏，不复制原型视觉。

### 1. 基础信息

- 任务名称、群组来源（历史老群 / 自收群 / 混合来源）、任务备注。
- 目标数据包选择、TXT 文件选择。
- 数据统计摘要：原始数量、有效数量、重复数量、格式错误、无效号码、未注册、已成功使用、其他任务预占、当前可用。

统计摘要在没有解析接口时统一显示 `--`；选择文件只展示文件名，不伪造解析结果或上传成功状态。

### 2. 目标群配置

- 群资源使用方式、是否清空当前群成员、是否禁言、群最大人数。
- 群名称修改方式、群头像、群描述。
- 群资料修改权限、入群审批、成员邀请权限。
- 目标群组选择与等待任务池页签。
- 筛选项：群组来源、所属大洲、所属国家、当前账号角色、群名称、群组状态、当前管理账号、群组 JID、是否显示普通成员群组、是否被其他任务占用、发言权限、入群审批、成员邀请权限、群存续天数、群当前人数。
- 可用数量摘要、全选可执行、加入等待任务池、跨页选择提示和候选群表格。

候选群数据依赖接口，前端先完成筛选模型、表格结构、选择状态和空状态；不内置原型中的示例群。

### 3. 角色账号与拉手配置

- 管理员、拉手、水军、营销账号四张资源卡，展示筛选条件摘要、可用数、占用数以及修改/清空入口。
- 参数：每群计划拉手数、每个拉手最多拉人数、单个拉手每次最多拉人数、两次拉人等待时间、最大使用拉手总数、最大使用群组数、连续异常群组上限、拉手最大重试次数、拉手熔断次数、拉手完成后退出群组、到达上限处理方式、每群计划水军人数、水军单任务入群上限、水军每日入群上限、允许跨任务复用、水军资源不足处理、允许降低计划数量、允许替换水军。

资源卡数据依赖后端时显示明确空态；参数控件可本地交互并保留单位和基础范围约束。

### 4. 目标数据与营销消息

- 营销发送间隔、营销模板、模板版本、推广链接、模板内容预览。
- 立即发送第一条、发送方式（固定轮次 / 固定持续时间）、固定发送轮次、消息发送总上限、失败重试次数、群组异常处理方式、营销开始方式。
- 水军最低成功标准、目标数据最低成功标准，均支持人数/成功率模式。
- 未达标处理方式：继续补充、更换拉手、更换水军、补充目标数据、重试、暂停当前群、允许部分完成、转人工、放弃当前群。

模板快照、内容预览和推广链接没有真实数据时显示 `--`，不使用原型示例内容冒充接口结果。

### 5. 任务启动时机

- 创建后立即开始 / 指定时间开始。
- 指定时间模式下展示日期时间选择器。
- 展示“邀请链接重置能力待后端确认”的提示。

### 底部操作

展示保存草稿、校验配置、预览任务、取消、创建并启动。取消可以直接返回列表；其余动作在本阶段不调用旧创建接口，统一给出“接口契约待确认，当前仅完成前端配置”的可见反馈。

## 组件边界

- 列表沿用 `index.vue`、`GroupPullMarketingTaskTable.vue` 和 `useGroupPullMarketingPage.ts`，新增纯展示格式化模块。
- 新建页容器负责路由、草稿状态和底部操作。
- 五个配置区块各自拆为局部组件；目标群筛选/表格和资源卡再按职责拆分，保证单个 `.vue` 文件不超过 600 行。
- 新建页草稿类型、默认值和选项集中在同域 TypeScript 文件，不放入 Pinia。
- 页面不得直接调用 Axios；未来接口确认后只在 `src/api/group-pull-marketing.ts` 与提交映射层接入。

## 状态与错误处理

- 列表加载、空列表、请求失败和分页继续使用现有模式；刷新失败时保留上一次成功数据。
- 新建页本地交互不依赖生产 mock；下拉候选为空时展示空状态，只读统计缺失时展示 `--`。
- 文件选择只接受 TXT；头像只做本地文件名/预览占位，不上传。
- 数字控件保留单位、最小值和明显上限约束；跨字段业务规则暂不宣称校验通过。
- 未接通的保存、校验、预览和创建动作必须有可见提示，不能无响应。

## 验证

- 列表契约测试：五项查询、九列顺序、缺失值与零值、现有任务操作和分页。
- 新建页结构测试：路由、五个区块、关键字段标签、底部动作和旧抽屉移除。
- 纯逻辑测试：默认草稿、条件字段显隐、人数/成功率模式及选择状态。
- 工程验证：相关 Node 测试、`pnpm typecheck`、相关 ESLint/Stylelint、`pnpm build`。

## 不在本次范围

- 后端接口、数据库、远程环境和部署。
- 真实目标数据包/TXT 解析、群组筛选、资源统计、模板快照或任务创建提交。
- 任务详情页与单群明细页重构。
- 从原型复制一套新的基础 UI 或生产演示数据。
